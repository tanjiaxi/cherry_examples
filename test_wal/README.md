# WAL 有状态服务模拟系统

本项目实现了一个完整的基于 Write-Ahead Log (WAL) 的有状态服务系统，模拟老虎机游戏场景中的玩家状态管理、WAL 分片机制和异步数据库同步。

## 系统架构

### 核心组件

1. **PlayerStateManager** (`player_state.go`)
   - 管理所有玩家的内存状态（余额、总下注、总赢取等）
   - 支持并发安全的状态更新
   - 提供快照导出/导入功能用于持久化和恢复

2. **WALSegmentManager** (`wal_segment.go`)
   - 实现 WAL 文件分片机制
   - 自动按大小或时间切换分片文件
   - 记录分片元数据和同步进度
   - 支持断点续传恢复

3. **DBSyncer** (`db_syncer.go`)
   - 异步数据库同步器
   - 从 WAL 分片读取数据批量同步
   - 同步速度故意比写入慢（模拟网络延迟）
   - 支持断点续传

4. **StatefulService** (`stateful_service.go`)
   - 有状态服务主控制器
   - 整合所有组件
   - 实现完整的启动-运行-恢复-关闭流程
   - 支持宕机恢复

## 关键特性

### 1. WAL 分片机制

WAL 文件自动分片，每个分片记录：
- 分片ID（wal_0001.log, wal_0002.log...）
- 起始序列号和结束序列号
- 同步状态标记

```json
{
  "current_segment_id": 3,
  "segments": [
    {"id": 1, "start_seq": 1, "end_seq": 1000, "synced": true},
    {"id": 2, "start_seq": 1001, "end_seq": 2000, "synced": true},
    {"id": 3, "start_seq": 2001, "end_seq": -1, "synced": false}
  ],
  "sync_progress": {
    "last_synced_segment": 2,
    "last_synced_sequence": 2000
  }
}
```

### 2. 宕机恢复流程

服务启动时自动执行：
1. 检查并加载玩家状态快照
2. 读取 WAL 元数据
3. 从上次同步点之后重放 WAL 记录
4. 恢复序列号生成器状态
5. 继续未完成的数据库同步
6. 创建新分片继续服务

### 3. 异步同步机制

- WAL 写入与数据库同步解耦
- 数据库同步比 WAL 写入慢（模拟真实网络环境）
- 分片级别的同步进度追踪
- 支持批量同步提升性能

### 4. 并发安全

- 所有玩家状态更新使用读写锁保护
- WAL 写入顺序性保证
- 序列号全局唯一递增
- 幂等性更新支持

## 技术亮点

### 1. 顺序写入性能优化
- WAL 使用缓冲区批量写入
- 单条记录固定40字节，序列化高效
- 支持 fsync 强制刷盘保证持久性

### 2. 分片管理
- 自动按大小或时间切换分片
- 元数据文件记录所有分片信息
- 支持分片级别的同步状态追踪

### 3. 幂等性保证
- 每条记录都有全局唯一递增序列号
- 玩家状态更新检查序列号避免重复执行
- 支持 WAL 重放恢复

### 4. 优雅关闭
- 停止数据生成
- 等待 WAL 刷盘
- 执行最后一次同步
- 保存状态快照
- 关闭所有资源
