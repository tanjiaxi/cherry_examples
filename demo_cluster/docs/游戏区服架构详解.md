# 游戏区服架构详解

## 1. 核心概念

### 1.1 三层架构关系

```
区组 (AreaGroup)
    ↓ 包含多个
区 (Area)
    ↓ 包含多个
服 (Server)
```

### 1.2 定义

- **区组 (AreaGroup)**: 最大的逻辑分组，通常用于跨区活动、排行榜等
- **区 (Area)**: 玩家登录时选择的大区，共享网关节点
- **服 (Server)**: 实际的游戏服务器，玩家创建角色的地方

## 2. 配置文件分析

### 2.1 区配置 (areaConfig.json)

```json
[
  {
    "areaId": 1,
    "areaName": "1区",
    "gateNodes": ["gc-gate-1"],      // 该区使用的网关节点
    "defaultGate": "127.0.0.1:20010" // 默认网关地址
  },
  {
    "areaId": 2,
    "areaName": "2区",
    "gateNodes": ["gc-gate-1"],
    "defaultGate": "127.0.0.1:20011"
  }
]
```

**关键字段：**
- `areaId`: 区ID，全局唯一
- `areaName`: 区名称，显示给玩家
- `gateNodes`: 该区使用的网关节点列表
- `defaultGate`: 默认网关地址（玩家连接入口）

### 2.2 服配置 (areaServerConfig.json)

```json
[
  {
    "serverId": 1,
    "serverName": "1服",
    "areaId": 1,                      // 所属区ID
    "gameNodes": ["10001", "10002"],  // 该服使用的游戏节点
    "status": 1                       // 服务器状态
  },
  {
    "serverId": 2,
    "serverName": "2服",
    "areaId": 2,                      // 属于2区
    "gameNodes": ["10001", "10002"],
    "status": 1
  },
  {
    "serverId": 3,
    "serverName": "3服",
    "areaId": 2,                      // 也属于2区
    "gameNodes": ["10001", "10002"],
    "status": 1
  }
]
```

**关键字段：**
- `serverId`: 服ID，全局唯一
- `serverName`: 服名称，显示给玩家
- `areaId`: 所属区ID（外键关联）
- `gameNodes`: 该服使用的游戏节点列表
- `status`: 服务器状态（1=正常，0=维护等）

### 2.3 区组配置 (areaGroupConfig.json)

```json
[
  {
    "pid": 2126001,                   // 区组ID ，现在游戏中就是渠道号，那个渠道来的，对应那个区列表
    "areaIdList": [1, 2]              // 包含的区列表
  },
  {
    "pid": 2126002,
    "areaIdList": [3, 4]
  }
]
```

**关键字段：**
- `pid`: 区组ID（可能是 Platform ID）
- `areaIdList`: 该区组包含的区ID列表

### 3.2 关系说明

1. **区组 → 区**: 一对多关系
   - 一个区组包含多个区
   - 用于跨区活动、排行榜等功能

2. **区 → 服**: 一对多关系
   - 一个区包含多个服
   - 玩家在区内选择服创建角色

3. **区 → 网关节点**: 多对多关系
   - 一个区可以有多个网关节点（负载均衡）
   - 一个网关节点可以服务多个区

4. **服 → 游戏节点**: 多对多关系
   - 一个服可以使用多个游戏节点（分布式）
   - 一个游戏节点可以服务多个服

## 4. 创建顺序

### 4.1 逻辑顺序

```
1. 先有区 (Area)
   ↓
2. 再有服 (Server)
   ↓
3. 最后有区组 (AreaGroup) - 可选
```

### 4.2 原因分析

**为什么先有区？**

1. **网络架构需要**: 区定义了网关节点，玩家需要先连接到网关
2. **逻辑隔离**: 区是最基本的逻辑隔离单位
3. **配置依赖**: 服配置需要引用区ID（`areaId` 字段）

**为什么后有服？**

1. **动态扩展**: 可以在区内动态增加服
2. **灵活配置**: 不同服可以使用不同的游戏节点
3. **玩家分流**: 根据玩家数量动态开服

**区组为什么可选？**

1. **高级功能**: 只有需要跨区功能时才需要
2. **后期配置**: 可以在运营过程中动态调整

## 5. 实际应用场景

### 5.1 玩家登录流程

```
1. 玩家选择区 (Area)
   ↓
2. 连接到该区的网关节点 (Gate)
   ↓
3. 玩家选择服 (Server)
   ↓
4. 网关将玩家路由到对应的游戏节点 (Game)
   ↓
5. 玩家在该服创建角色或登录角色
```

### 5.2 代码示例

```go
// 1. 玩家选择区
func SelectArea(areaId int) (*AreaConfig, error) {
    // 从 areaConfig.json 加载区配置
    area := LoadAreaConfig(areaId)
    if area == nil {
        return nil, errors.New("区不存在")
    }
    return area, nil
}

// 2. 获取该区的服列表
func GetServerList(areaId int) ([]*ServerConfig, error) {
    // 从 areaServerConfig.json 加载服配置
    servers := LoadServersByAreaId(areaId)
    return servers, nil
}

// 3. 玩家选择服
func SelectServer(serverId int) (*ServerConfig, error) {
    server := LoadServerConfig(serverId)
    if server == nil {
        return nil, errors.New("服不存在")
    }
    
    // 检查服务器状态
    if server.Status != 1 {
        return nil, errors.New("服务器维护中")
    }
    
    return server, nil
}

// 4. 路由到游戏节点
func RouteToGameNode(serverId int, playerId int64) (string, error) {
    server := LoadServerConfig(serverId)
    
    // 根据玩家ID哈希到某个游戏节点
    nodeIndex := playerId % int64(len(server.GameNodes))
    gameNodeId := server.GameNodes[nodeIndex]
    
    return gameNodeId, nil
}
```

## 6. 节点类型说明

### 6.1 节点架构

```
┌─────────────────────────────────────────────────────────┐
│                    Cherry 集群架构                       │
│                                                          │
│  ┌──────────┐                                           │
│  │  Master  │  - 主节点，管理集群                       │
│  └────┬─────┘                                           │
│       │                                                  │
│  ┌────┴─────┐                                           │
│  │  Center  │  - 中心节点，账号、位置管理               │
│  └────┬─────┘                                           │
│       │                                                  │
│  ┌────┴─────────────────────────────┐                  │
│  │                                   │                  │
│  ↓                                   ↓                  │
│ ┌──────────┐                    ┌──────────┐           │
│ │   Gate   │ ← 玩家连接         │   Web    │           │
│ │  (网关)  │                    │ (HTTP)   │           │
│ └────┬─────┘                    └──────────┘           │
│      │                                                  │
│      ↓                                                  │
│ ┌──────────┐                                           │
│ │   Game   │  - 游戏逻辑节点                           │
│ │ (10001)  │                                           │
│ └──────────┘                                           │
│ ┌──────────┐                                           │
│ │   Game   │                                           │
│ │ (10002)  │                                           │
│ └──────────┘                                           │
└─────────────────────────────────────────────────────────┘
```

### 6.2 节点说明

| 节点类型 | 节点ID示例 | 作用 | 与区服的关系 |
|---------|-----------|------|-------------|
| Master | gc-master | 集群管理 | 全局唯一，不属于任何区服 |
| Center | gc-center | 账号、位置管理 | 全局唯一，管理所有区服 |
| Gate | gc-gate-1 | 玩家连接入口 | 一个区可以有多个网关 |
| Game | 10001, 10002 | 游戏逻辑 | 一个服可以使用多个游戏节点 |
| Web | gc-web-1 | HTTP API | 全局服务，不属于特定区服 |

## 8. 常见问题

### 8.1 为什么一个区可以有多个服？

**答案：** 
- 分流玩家，避免单服过载
- 新服可以吸引新玩家
- 老服可以保持老玩家社交关系

### 8.2 为什么多个服可以共享游戏节点？

**答案：**
- 资源复用，节省服务器成本
- 动态负载均衡
- 玩家数据隔离在逻辑层（serverId）

### 8.3 区组的作用是什么？

**答案：**
- 跨区排行榜
- 跨区活动（如跨服战）
- 跨区交易市场
- 合区操作的基础

### 8.4 如何实现合区？

**答案：**
```json
// 合区前
{
  "serverId": 1,
  "serverName": "1服",
  "areaId": 1,
  "gameNodes": ["10001"],
  "status": 1
}
{
  "serverId": 2,
  "serverName": "2服",
  "areaId": 1,
  "gameNodes": ["10002"],
  "status": 1
}

// 合区后
{
  "serverId": 1,
  "serverName": "1服(合)",
  "areaId": 1,
  "gameNodes": ["10001", "10002"],  // 合并游戏节点
  "status": 1
}
{
  "serverId": 2,
  "serverName": "2服",
  "areaId": 1,
  "gameNodes": [],
  "status": 0  // 关闭
}
```

## 9. 总结

### 9.1 核心要点

1. **创建顺序**: 区 → 服 → 区组
2. **层级关系**: 区组包含区，区包含服
3. **节点关系**: 区关联网关节点，服关联游戏节点
4. **逻辑隔离**: 玩家数据按服隔离，但可以跨区活动

### 9.2 设计优势

- **灵活扩展**: 可以动态增加区、服、节点
- **负载均衡**: 多网关、多游戏节点分担压力
- **资源复用**: 节点可以被多个服共享
- **运营灵活**: 支持开服、合服、跨服等运营需求

### 9.3 配置文件关系图

```
areaGroupConfig.json (区组配置)
    ↓ 引用
areaConfig.json (区配置)
    ↓ 被引用
areaServerConfig.json (服配置)
    ↓ 引用
demo-cluster.json (节点配置)
```

这种架构设计是游戏服务器的经典模式，既保证了性能和扩展性，又满足了运营的灵活性需求。
