```
# 1. 接收登录请求
[GATE-IN] route=gate.user.login, uid=0, sid=abc123, mid=1, size=256 bytes

# 2. 返回登录响应（Info 级别）

```

## 方案优势

| 特性 | 说明 |
|------|------|
| ✅ 零侵入 | 上层业务代码完全不需要修改 |
| ✅ 全覆盖 | 自动覆盖所有 Response/Push/Kick 调用 |
| ✅ 真正统一 | 在框架层面实现统一日志 |
| ✅ 易维护 | 只需修改一处底层代码 |
| ✅ 高性能 | 使用 PrintLevel 避免不必要的序列化 |

## 性能优化

### 日志级别控制
```go
// Info 级别 - 不序列化，性能最优
clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d", ...)

// Debug 级别 - 只在需要时序列化
if clog.PrintLevel(zapcore.DebugLevel) {
    if payload, err := a.Serializer().Marshal(v); err == nil {
        clog.Debugf("[GATE-OUT-DETAIL] resp=%s", string(payload))
    }
}
```

### 配置示例
```json
{
  "logger": {
    "gate_log": {
      "level": "info",     // 生产环境：只打印简要信息
      "enable_console": true
    }
  }
}
```

## 关于修改 vendor 代码

### 为什么可以修改？
1. Cherry 是你们自己的框架，不是第三方库
2. vendor 目录会提交到 git，团队共享修改
3. 统一管理，所有项目使用相同的修改

### 如何管理修改？
1. 在修改处添加注释标记：`// [CUSTOM] 添加统一消息日志`
2. 在项目文档中记录框架修改点
3. 框架升级时，重新应用这些修改
