# 消息打印方案

## 1. 打印策略

### 1.1 分层打印原则

```
客户端 → Gate → Game
         ↓       ↓
      简要日志  详细日志
```

- **Gate 层**: 打印简要信息（路由、用户、大小）
- **Game 层**: 打印详细信息（完整请求/响应）

### 1.2 日志级别

- **Info**: Gate 层的消息流量统计
- **Debug**: Game 层的详细请求/响应
- **Warn**: 异常消息、错误路由

## 2. Gate 层实现

### 2.1 在 route.go 添加消息打印

```go
// onPomeloDataRoute 数据路由规则
func onPomeloDataRoute(agent *pomelo.Agent, route *pmessage.Route, msg *pmessage.Message) {
    startTime := msg.StartTime
    if startTime.IsZero() {
        startTime = time.Now()
    }

    routeName := msg.Route
    metrics.RecordRequest(routeName)

    // ========== 添加消息打印 ==========
    session := pomelo.BuildSession(agent, msg)
    
    // 打印接收到的消息（简要信息）
    clog.Infof("[GATE-IN] route=%s, uid=%d, sid=%s, mid=%d, size=%d bytes", 
        msg.Route, 
        session.Uid, 
        session.Sid,
        msg.ID, 
        len(msg.Data))
    // ===================================

    hasError := false
    defer func() {
        metrics.RecordResponse(routeName, startTime, hasError)
        
        // 打印处理完成（可选）
        elapsed := time.Since(startTime)
        if elapsed > 100*time.Millisecond {
            clog.Warnf("[GATE-SLOW] route=%s, uid=%d, elapsed=%v", 
                msg.Route, session.Uid, elapsed)
        }
    }()

    // ... 原有逻辑 ...
}
```

```go
// login 函数中添加响应打印
func (p *ActorAgent) login(session *cproto.Session, req *pb.LoginRequest) {
    done := metrics.TrackRequest("gate.actor.login")
    defer done(false)
    
    agent, found := pomelo.GetAgent(p.ActorID(), session.Uid)
    if !found {
        return
    }

    // 打印登录请求
    clog.Infof("[GATE-LOGIN-IN] sid=%s, token=%s...", 
        session.Sid, req.Token[:20])

    // ... 原有逻辑 ...

    response := &pb.LoginResponse{
        UserId: userId,
        Pid:    userToken.PID,
        OpenId: userToken.OpenID,
    }

    // 打印登录响应

        session.Sid, userId, userToken.PID, userToken.OpenID)

    agent.Response(session, response)
}
```

## 3. Game 层实现

### 3.1 创建消息打印中间件

创建文件：`demo_cluster/internal/middleware/message_logger.go`

```go
package middleware

import (
    "encoding/json"
    "time"

    clog "github.com/cherry-game/cherry/logger"
    cproto "github.com/cherry-game/cherry/net/proto"
)

// LogRequest 打印请求消息
func LogRequest(route string, session *cproto.Session, req interface{}) {
    if !clog.IsDebugEnabled() {
        return
    }

    reqJSON, _ := json.Marshal(req)
    clog.Debugf("[GAME-IN] route=%s, uid=%d, req=%s", 
        route, session.Uid, string(reqJSON))
}

// LogResponse 打印响应消息
func LogResponse(route string, session *cproto.Session, resp interface{}, elapsed time.Duration) {
    if !clog.IsDebugEnabled() {
        return
    }

    respJSON, _ := json.Marshal(resp)
    clog.Debugf("[GAME-OUT] route=%s, uid=%d, elapsed=%v, resp=%s", 
        route, session.Uid, elapsed, string(respJSON))
}

// LogError 打印错误消息
func LogError(route string, session *cproto.Session, errCode int32, err error) {
    clog.Warnf("[GAME-ERROR] route=%s, uid=%d, errCode=%d, err=%v", 
        route, session.Uid, errCode, err)
}
```

### 3.2 在 Game Actor 中使用

示例：`demo_cluster/nodes/game/module/player/actor_player.go`

```go

}
```

## 6. 性能考虑

### 6.1 避免性能影响

```go
// ❌ 错误：总是序列化
func LogRequest(route string, req interface{}) {
    reqJSON, _ := json.Marshal(req)  // 即使不打印也会序列化
    clog.Debugf("req=%s", string(reqJSON))
}

// ✅ 正确：先检查日志级别
func LogRequest(route string, req interface{}) {
    if !clog.IsDebugEnabled() {
        return  // 直接返回，不序列化
    }
    reqJSON, _ := json.Marshal(req)
    clog.Debugf("req=%s", string(reqJSON))
}
```

### 6.2 使用采样

```go
// 只打印 10% 的消息
var messageLogSampleRate = 0.1

func LogRequest(route string, req interface{}) {
    if rand.Float64() > messageLogSampleRate {
        return
    }
    // ... 打印逻辑
}
```

### 6.3 异步打印

```go
// 使用 channel 异步打印
var logChan = make(chan string, 1000)

func init() {
    go func() {
        for msg := range logChan {
            clog.Debug(msg)
        }
    }()
}

func LogRequest(route string, req interface{}) {
    reqJSON, _ := json.Marshal(req)
    select {
    case logChan <- fmt.Sprintf("[GAME-IN] route=%s, req=%s", route, string(reqJSON)):
    default:
        // channel 满了，丢弃日志
    }
}
```

## 7. 实用工具函数

### 7.1 格式化打印

```go
// 美化 JSON 输出
func PrettyJSON(v interface{}) string {
    b, err := json.MarshalIndent(v, "", "  ")
    if err != nil {
        return fmt.Sprintf("%+v", v)
    }
    return string(b)
}

// 使用
clog.Debugf("[GAME-IN] route=%s, req=\n%s", route, PrettyJSON(req))
```

### 7.2 敏感信息脱敏

```go
// 脱敏函数
func MaskSensitive(s string) string {
    if len(s) <= 8 {
        return "***"
    }
    return s[:4] + "***" + s[len(s)-4:]
}

// 使用
clog.Infof("[GATE-LOGIN-IN] token=%s", MaskSensitive(req.Token))
```

## 8. 推荐方案

### 8.1 开发环境

```
Gate 层: Info 级别（打印所有消息路由）
Game 层: Debug 级别（打印详细请求/响应）
```

### 8.2 生产环境

```
Gate 层: Info 级别（只打印关键消息）
Game 层: Info 级别（不打印详细数据）
+ 错误日志: Warn/Error 级别
+ 慢请求日志: 超过阈值才打印
```

### 8.3 压测环境

```
Gate 层: Warn 级别（只打印错误）
Game 层: Warn 级别（只打印错误）
+ 性能统计: 使用 metrics 组件
```

## 9. 总结

| 层级 | 打印内容 | 日志级别 | 适用场景 |
|------|---------|---------|---------|
| Gate | 路由、用户、大小 | Info | 网络监控、路由排查 |
| Game | 完整请求/响应 | Debug | 业务调试、逻辑排查 |
| 错误 | 错误码、错误信息 | Warn/Error | 异常监控 |
| 慢请求 | 耗时、路由 | Warn | 性能优化 |

**最佳实践：**
1. Gate 层打印简要信息（总是开启）
2. Game 层打印详细信息（开发时开启，生产关闭）
3. 使用日志级别控制打印详细程度
4. 注意性能影响，先检查日志级别再序列化
5. 敏感信息要脱敏
