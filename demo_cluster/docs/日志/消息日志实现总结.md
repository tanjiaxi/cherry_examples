# 统一消息日志实现总结

## 实现状态：✅ 已完成

## 实现内容

### 1. 中间件实现
**文件**: `demo_cluster/internal/middleware/message_logger.go`

**提供的功能**:
- `LogResponse()` - 统一打印响应消息
- `LogPush()` - 统一打印推送消息  
- `LogKick()` - 统一打印踢人消息
- `MessageTracker` - 消息生命周期跟踪器
- `AgentWrapper` - Agent 包装器（自动打印）

**日志格式**:
```
[GATE-OUT] uid=10001, sid=abc123, mid=1                    # Info 级别
[GATE-OUT-DETAIL] uid=10001, sid=abc123, mid=1, resp={...} # Debug 级别
```

### 2. Gate 层集成
**文件**: `demo_cluster/nodes/gate/actor_agent.go`

**已更新的函数**:
- `login()` - 登录响应（成功和失败情况）

**修改示例**:
```go
// 原来
agent.Response(session, response)

// 现在
middleware.LogResponse(agent, session, response)
```

### 3. 接收消息日志
**文件**: `demo_cluster/nodes/gate/route.go`

**已有的日志**:
```go
clog.Infof("[GATE-IN] route=%s, uid=%d, sid=%s, mid=%d, size=%d bytes",
    msg.Route, session.Uid, session.Sid, msg.ID, len(msg.Data))
```

## 使用方法

### 基本用法
```go
import "github.com/cherry-game/examples/demo_cluster/internal/middleware"

// 打印响应
middleware.LogResponse(agent, session, response)

// 打印推送
middleware.LogPush(agent, route, data)

// 打印踢人
middleware.LogKick(agent, reason, closed)
```

### 日志级别控制

在 `config/demo-cluster.json` 中配置:
```json
{
  "logger": {
    "gate_log": {
      "level": "info",  // info: 简要日志, debug: 详细日志
      "enable_console": true
    }
  }
}
```

## 日志输出示例

### 完整的消息流
```
# 1. 接收登录请求
[GATE-IN] route=gate.user.login, uid=0, sid=abc123, mid=1, size=256 bytes

# 2. 返回登录响应（Info 级别）
[GATE-OUT] uid=10001, sid=abc123, mid=1

# 3. 返回登录响应（Debug 级别）
[GATE-OUT-DETAIL] uid=10001, sid=abc123, mid=1, resp={"userId":10001,"pid":2126001,"openId":"test_user"}
```

## 性能优化

### 日志级别自动控制
- Cherry logger 会根据配置的日志级别自动决定是否输出
- Info 级别: 只输出简要信息（uid, sid, mid）
- Debug 级别: 额外输出详细的 JSON 数据
- 当日志级别设置为 Warn 或更高时，Info 和 Debug 日志都不会输出

### 序列化优化
```go
// Info 级别 - 不序列化，性能最优
clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d", ...)

// Debug 级别 - 序列化 JSON，仅在需要时执行
respJSON, _ := json.Marshal(v)
clog.Debugf("[GATE-OUT-DETAIL] resp=%s", string(respJSON))
```
