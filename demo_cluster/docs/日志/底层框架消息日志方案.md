# 底层框架消息日志方案（最优方案）

## 方案概述

直接在 Cherry 框架的 Agent 底层实现中添加统一的消息日志，上层业务代码完全不需要修改。

## 方案优势

✅ **零侵入**: 上层代码完全不需要修改  
✅ **全覆盖**: 自动覆盖所有 `agent.Response()`、`agent.Push()`、`agent.Kick()` 调用  
✅ **真正统一**: 在框架层面实现统一日志  
✅ **易维护**: 只需修改一处底层代码  
✅ **性能优化**: 使用 `clog.PrintLevel()` 避免不必要的序列化

## 实现位置

**文件**: `vendor/github.com/cherry-game/cherry/net/parser/pomelo/agent.go`

### 修改的方法

1. `Response()` - 响应消息
2. `Push()` - 推送消息
3. `Kick()` - 踢人消息

## 实现代码

### 1. Response 方法

```go
func (a *Agent) Response(session *cproto.Session, v interface{}, isError ...bool) {
	// 统一打印响应消息（Info 级别）
	clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d",
		session.Uid, session.Sid, session.GetMID())
	
	// 详细日志（Debug 级别）
	if clog.PrintLevel(zapcore.DebugLevel) {
		if payload, err := a.Serializer().Marshal(v); err == nil {
			clog.Debugf("[GATE-OUT-DETAIL] uid=%d, sid=%s, mid=%d, resp=%s",
				session.Uid, session.Sid, session.GetMID(), string(payload))
		}
	}
	
	a.ResponseMID(session.GetMID(), v, isError...)
}
```

### 2. Push 方法

```go
func (a *Agent) Push(route string, val interface{}) {
	// 统一打印推送消息（Info 级别）
	clog.Infof("[GATE-PUSH] uid=%d, sid=%s, route=%s",
		a.UID(), a.SID(), route)
	
	// 详细日志（Debug 级别）

		if payload, err := a.Serializer().Marshal(val); err == nil {
			clog.Debugf("[GATE-PUSH-DETAIL] uid=%d, sid=%s, route=%s, data=%s",
				a.UID(), a.SID(), route, string(payload))
		}
	}
	
	a.sendPending(pomeloMessage.Push, route, 0, val, false)
	// ... 原有代码 ...
}
```

## 性能优化

### 1. 日志级别检查
使用 `clog.PrintLevel(zapcore.DebugLevel)` 在序列化之前检查日志级别：

```go
// 只在 Debug 级别才序列化
if clog.PrintLevel(zapcore.DebugLevel) {
    if payload, err := a.Serializer().Marshal(v); err == nil {
        clog.Debugf("[GATE-OUT-DETAIL] resp=%s", string(payload))
    }
}
```

**优势**:
- Info 级别时不会执行 `Marshal()` 序列化操作
- 避免了不必要的 CPU 和内存开销
- 生产环境性能影响极小

### 2. 错误处理
序列化失败时不影响正常业务流程：

```go
if payload, err := a.Serializer().Marshal(v); err == nil {
    // 只在成功时打印
    clog.Debugf("...")
}
// 失败时静默忽略，不影响业务
```

## 关于修改 vendor 代码

### 为什么可以修改 vendor？

1. **Cherry 是你们自己的框架**: 不是第三方库，可以自由修改
2. **统一管理**: 所有项目使用相同的 vendor，修改一次全部生效
3. **版本控制**: vendor 目录通常会提交到 git，团队共享修改

### 如何管理修改

1. **记录修改**: 在框架代码中添加注释
   ```go
   // [CUSTOM] 添加统一消息日志 - 2024/03/24
   clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d", ...)
   ```

2. **文档说明**: 在项目文档中记录框架修改点

3. **升级策略**: 框架升级时，重新应用这些修改
