# 底层统一消息打印方案

## 1. 方案概述

通过在框架的关键位置添加统一的消息打印，无需在每个接口手动添加日志代码。

### 1.1 打印位置

```
客户端 → Gate → Game
         ↓       ↓
    route.go  middleware
    (接收)    (发送)
```

## 2. 已实现的统一打印点

### 2.1 Gate 层接收消息（已完成）

**位置**: `demo_cluster/nodes/gate/route.go` 的 `onPomeloDataRoute` 函数

**打印内容**:
```go
clog.Infof("[GATE-IN] route=%s, uid=%d, sid=%s, mid=%d, size=%d bytes",
    msg.Route, session.Uid, session.Sid, msg.ID, len(msg.Data))
```

**特点**:
- ✅ 自动打印所有接收到的消息
- ✅ 无需在每个接口添加代码
- ✅ 包含路由、用户、消息大小等关键信息

### 2.2 Gate 层发送消息（新增）

**位置**: `demo_cluster/internal/middleware/message_logger.go`

**提供的函数**:

```go
// 1. 打印响应消息
middleware.LogResponse(agent, session, response)

// 2. 打印推送消息
middleware.LogPush(agent, route, data)

// 3. 打印踢人消息
middleware.LogKick(agent, reason, closed)
```

## 3. 使用方法

### 3.1 在 Actor 中使用（推荐）

**原来的代码**:
```go
func (p *ActorAgent) login(session *cproto.Session, req *pb.LoginRequest) {
    // ... 业务逻辑 ...
    
    response := &pb.LoginResponse{
        UserId: userId,
        Pid:    userToken.PID,
        OpenId: userToken.OpenID,
    }
    
    agent.Response(session, response)  // 原始方法
}
```

**修改后的代码**:
```go
import "github.com/cherry-game/examples/demo_cluster/internal/middleware"

func (p *ActorAgent) login(session *cproto.Session, req *pb.LoginRequest) {
    // ... 业务逻辑 ...
    
    response := &pb.LoginResponse{
        UserId: userId,
        Pid:    userToken.PID,
        OpenId: userToken.OpenID,
    }
    
    // 使用中间件，自动打印响应
    middleware.LogResponse(agent, session, response)
}
```

### 3.2 批量替换方法

使用 IDE 的查找替换功能：

**查找**: `agent.Response(session,`
**替换**: `middleware.LogResponse(agent, session,`

**查找**: `agent.Push(`
**替换**: `middleware.LogPush(agent,`

**查找**: `agent.Kick(`
**替换**: `middleware.LogKick(agent,`

## 5. 高级用法

### 5.1 消息跟踪器（完整生命周期）

```go
import "github.com/cherry-game/examples/demo_cluster/internal/middleware"

func (p *ActorPlayer) enter(session *cproto.Session, req *pb.EnterRequest) {
    // 创建消息跟踪器
    tracker := middleware.NewMessageTracker(
        "game.player.enter", 
        session.Uid, 
        session.Sid, 
        session.GetMID(),
    )
    
    // 记录请求
    reqData, _ := json.Marshal(req)
    tracker.LogRequest(reqData)
    
    // 业务逻辑
    response, err := p.processEnter(req)
    if err != nil {
        tracker.LogError(code.EnterFailed, err)
        return
    }
    
    // 记录响应
    tracker.LogResponse(response)
    
    // 发送响应
    middleware.LogResponse(agent, session, response)
}
```

**输出**:
```
[MSG-IN] route=game.player.enter, uid=10001, sid=abc123, mid=2, size=128 bytes
[MSG-IN-DETAIL] route=game.player.enter, uid=10001, data={"serverId":1}
[MSG-OUT] route=game.player.enter, uid=10001, sid=abc123, mid=2, elapsed=15ms
[MSG-OUT-DETAIL] route=game.player.enter, uid=10001, elapsed=15ms, resp={...}
[GATE-OUT] uid=10001, sid=abc123, mid=2
```

### 5.2 Agent 包装器（自动打印）

```go
import "github.com/cherry-game/examples/demo_cluster/internal/middleware"

func (p *ActorAgent) login(session *cproto.Session, req *pb.LoginRequest) {
    agent, found := pomelo.GetAgent(p.ActorID(), session.Uid)
    if !found {
        return
    }
    
    // 包装 Agent，所有方法自动打印
    wrappedAgent := middleware.WrapAgentWithLog(agent)
    
    // ... 业务逻辑 ...
    
    response := &pb.LoginResponse{
        UserId: userId,
        Pid:    userToken.PID,
        OpenId: userToken.OpenID,
    }
    
    // 自动打印
    wrappedAgent.Response(session, response)
}
```

## 7. 性能优化

### 7.1 避免不必要的序列化

```go
func LogResponse(agent *pomelo.Agent, session *cproto.Session, v interface{}, isError ...bool) {
    // 先打印简要日志（总是执行）
    if clog.IsInfoEnabled() {
        clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d", 
            session.Uid, session.Sid, session.GetMID())
    }
    
    // 只在 Debug 级别才序列化（避免性能损失）
    if clog.IsDebugEnabled() {
        respJSON, _ := json.Marshal(v)
        clog.Debugf("[GATE-OUT-DETAIL] uid=%d, resp=%s", 
            session.Uid, string(respJSON))
    }
    
    // 调用原始方法
    agent.Response(session, v, isError...)
}
```

### 7.2 采样打印（高并发场景）

```go
import "math/rand"

var messageSampleRate = 0.1  // 只打印 10% 的消息

func LogResponse(agent *pomelo.Agent, session *cproto.Session, v interface{}, isError ...bool) {
    // 采样判断
    shouldLog := rand.Float64() < messageSampleRate
    
    if shouldLog && clog.IsInfoEnabled() {
        clog.Infof("[GATE-OUT] uid=%d, sid=%s, mid=%d", 
            session.Uid, session.Sid, session.GetMID())
    }
    
    agent.Response(session, v, isError...)
}
```

## 9. 总结

### 9.1 优点

✅ **统一管理**: 所有消息打印在一个地方控制
✅ **无侵入性**: 不需要修改业务逻辑
✅ **易于维护**: 修改日志格式只需改一处
✅ **性能可控**: 通过日志级别控制详细程度
✅ **灵活配置**: 支持动态开关和采样

### 9.2 使用建议

**开发环境**:
```
日志级别: Debug
打印详细: 是
采样率: 100%
```

**生产环境**:
```
日志级别: Info
打印详细: 否
采样率: 10% (可选)
```

**压测环境**:
```
日志级别: Warn
打印详细: 否
采样率: 1% (可选)
```

### 9.3 快速开始

1. 确保 `route.go` 中的接收消息打印已启用
2. 在需要打印响应的地方，将 `agent.Response` 替换为 `middleware.LogResponse`
3. 调整日志级别到 `info` 或 `debug`
4. 运行程序，查看日志输出

就这么简单！无需在每个接口手动添加日志代码。
